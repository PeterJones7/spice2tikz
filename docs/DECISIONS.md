# spice2tikz — Decision log

Append-only log of small implementation decisions taken while resolving
ambiguities, per `CLAUDE.md` working rule 8. One line per decision, newest
last. Final architectural decisions live in `docs/DESIGN.md` §4 (D1–D16) and
are not recorded here.

Format: `YYYY-MM-DD | roadmap § | decision — rationale`

- 2026-07-28 | 0.1 | Build backend is `hatchling`, version read from `src/spice2tikz/__init__.py` — single source of truth for `__version__`, no runtime dependency implied.
- 2026-07-28 | 0.1 | Copyright holder in `LICENSE` is "spice2tikz contributors" — avoids stamping an individual's name into the repository.
- 2026-07-28 | 0.2 | ruff line length 88 with `E,W,F,I,B,C4,UP,SIM,RUF,ANN,D,PTH` selected — docstrings and annotations are enforced from the start, since `mypy --strict` is required anyway.
- 2026-07-28 | 0.2 | CI matrix is Python 3.10 and 3.12 only (per roadmap), with ruff and mypy run once on 3.12 — lint/type results are Python-version-independent here.
- 2026-07-28 | 1.1 | Added `src/spice2tikz/_serde.py` (not in the CLAUDE.md target layout) holding the JSON primitives shared by both IR modules — version/unknown-field/type-check handling would otherwise be duplicated; the leading underscore marks it internal.
- 2026-07-28 | 1.1 | Loader diagnostics use an optional `warnings: list[str]` sink parameter rather than the `warnings` module or global state — deterministic, testable, and the caller decides where they go.
- 2026-07-28 | 1.1 | An optional IR field present but explicitly `null` is an `IRError`, not a silently-absent field — SPEC_IR requires omission, and a clear parse error beats guessing.
- 2026-07-28 | 1.1 | A SPICE number carries an exponent *or* a scale suffix, never both (`3.3e-6F` is 3.3 µ with unit F); trailing unit text is canonicalised when recognised and otherwise ignored, as SPICE ignores it.
- 2026-07-28 | 1.1 | Consequently `1F` parses as 1 femto (SPICE reads `F` as the femto scale factor); the `raw` text is always preserved so nothing is lost.
- 2026-07-28 | 1.1 | Text left over after the suffix that is not purely alphabetic (`1k*2`, `1k 2`) makes the value unparseable → `Quantity(raw=...)` only, rather than silently dropping the remainder.
- 2026-07-28 | 1.1 | Scale suffixes are stored as powers of ten and applied through a float literal (`100n` → `float("100e-9")`) — exact decimal scaling, so values match the spec examples bit-for-bit.
- 2026-07-28 | 1.1 | Suffix set is exactly the roadmap list (f p n u µ/μ m k meg g t); `mil` is not a suffix (its unit text is ignored instead).
- 2026-07-28 | 1.2 | `Kind` is a `str`-subclass `Enum` with `__str__` returning its value — comparisons and f-strings behave like the JSON text on every supported Python version, while typos are caught at load time.
- 2026-07-28 | 1.2 | `ir` and `version` are `ClassVar`s, not dataclass fields — they are properties of the format, not of a document, and this keeps round-trip equality about content.
- 2026-07-28 | 1.2 | `SubcktDef` serialises as `ports`, `params?`, `components`, `nets` (declaration order of "extends Scope"); `subcircuits` is always emitted (spec §5 shows `{}`) while empty `models` is omitted, being optional.
- 2026-07-28 | 1.2 | Net dictionaries and component lists keep insertion order rather than being sorted — determinism comes from preserving source order, which also keeps diffs readable (D9).
- 2026-07-28 | 1.3 | `SymbolDef`/`PinDef` live in `symbols.py` (imported by `schematic_ir.py`) rather than the other way round — the geometry type and the rotation/mirror maths that consume it stay together, and there is no import cycle.
- 2026-07-28 | 1.3 | Built-in transistor geometry is a 4×4 box with the control terminal at (-2, 0) and the two channel terminals at (2, ±2), MOS bulk at (2, 0) — mirrors the circuitikz transistor anchors (G/B left, D up, S down) on even grid coordinates so half-boxes stay integral.
- 2026-07-28 | 1.3 | `pmos` reuses the `nmos` offsets (drain up, source down) rather than swapping them: circuitikz anchors are geometric, and pin positions are explicit in the IR anyway, so orientation is the placer's job.
- 2026-07-28 | 1.3 | Loading keeps fractional coordinates verbatim instead of rejecting them, so `validate.py` reports them as invariant-6 errors (exit 2) rather than the loader failing as a parse error (exit 1); whole-number floats are normalised to `int`.
- 2026-07-28 | 1.3 | Canonical JSON follows SPEC_IR literally (`json.dumps(indent=2)`), so coordinate pairs serialise across several lines; the compact pairs in SPEC_IR §5 are illustrative formatting, not the output format.
- 2026-07-28 | 1.3 | `style` fields absent from a file fall back to the documented defaults instead of being an error — hand-written schematics can carry a partial style block.
- 2026-07-28 | 1.4 | `Finding` is a `NamedTuple` of exactly `(severity, message, location)` — matches the roadmap's contract and unpacks like a tuple, while still being readable by attribute.
- 2026-07-28 | 1.4 | Findings are emitted invariant by invariant (6, 7, 8, … 13) and in document order within each, never sorted by severity — the report order is part of the deterministic output.
- 2026-07-28 | 1.4 | Invariant 5 also warns when a flat design declares *more than one* ground-class net, not only when it declares none: "exactly one" is the invariant, but neither direction is fatal.
- 2026-07-28 | 1.4 | Added two checks in the spirit of their neighbours: a net's dictionary key must equal its `name` (SPEC_IR §1 says `net_id == name`), and a ccvs/cccs without `control` is an error (invariant 3 is meaningless otherwise).
- 2026-07-28 | 1.4 | `tap` net symbols are annotations, not conductors, for invariants 9 and 10 — a voltage label next to two pins must not demand a junction dot; ground/supply/sground symbols do connect.
- 2026-07-28 | 1.4 | Conductor counting at a point: a wire end counts 1, a wire passing through counts 2, each component pin, port, or connecting net symbol counts 1. Net identity is not consulted, since path components carry no net in the Schematic IR.
- 2026-07-28 | 1.4 | Invariant 12 reports only genuine overlaps: positive-area intersections, or two flattened boxes overlapping along the same line (two path components drawn on top of each other). Components that merely touch at a point or along an edge are how circuits connect. Bounding boxes are compared in doubled units so odd symbol sizes stay exact.
- 2026-07-28 | 1.4 | Invariant 9 accepts a wire end that lands anywhere on another same-net wire, including mid-segment (a T), but not on a wire of a different net.
- 2026-07-28 | 1.5 | `INPUT` is optional in the parser so that a bare `spice2tikz` prints usage and exits 1 rather than argparse's exit 2, which the CLI contract reserves for validation errors.
- 2026-07-28 | 1.5 | Input formats that are on the roadmap but unimplemented (`spice`, `asc`) report "not implemented yet" and exit 1 — the file cannot be read, so it is an input error rather than an internal one.
- 2026-07-28 | 1.5 | A `.json` input with no `--from` is dispatched on its `ir` field; every diagnostic goes to stderr, keeping stdout free for the emitted LaTeX from section 2 onwards.
- 2026-07-28 | 1.5 | `-q` suppresses warnings and the summary but never errors; `-v` adds the detected format and a one-line description of the loaded document.
- 2026-07-28 | 1.2 | **SPEC_IR §0 amended** (with the user's approval): canonical JSON is now produced by a dedicated printer instead of `json.dumps(indent=2)`. Objects still put one field per line, but arrays of scalars — and arrays of arrays of scalars — are inlined when they fit in 88 columns, so coordinates read as `"a": [0, 4]` and `"points": [[0, 0], [6, 0]]`. Rationale: `json.dumps` spread every coordinate over three lines, which made the hand-tweak workflow (DESIGN §2) and future golden IR files far worse; field order, determinism, and line-oriented diffs are unchanged.
- 2026-07-28 | 2.1 | circuitikz's own default resistor/capacitor style is European: the SPEC_IR §5 golden emission needs no override at all even though its `style` block says `"resistor_variant": "european"`, so `_variant_options` only ever emits `\ctikzset{american resistors/capacitors}`, and only when the style overrides to american.
- 2026-07-28 | 2.1 | Resolved a tension between D12 ("LaTeX injection allowed ONLY in `Label.text` (explicit), `extra_preamble`, `circuitikz_options`") and SPEC_IR §2's own, more specific wording for `LabelSpec.text` ("explicit → verbatim"): explicit `LabelSpec.text` (on a component's `label`/`value_label`) is emitted verbatim, matching the hand-tweak escape-hatch philosophy (DESIGN §2); D12's list is read as non-exhaustive. Everything else derived (refdes labels, unparseable quantity fallback text, `NetSymbol.text`, `Port.name`) is escaped per D12.
- 2026-07-28 | 2.1 | A path component's ref/value label folds into the bipole slot (`to[R=$R_1$]`) only when it resolves to circuitikz's default label side (`l=`); a flipped side (`l_=`) stays a separate option (`to[vsource, l_=$V_1$]`), matching the SPEC_IR §5 normative example exactly for both cases.
- 2026-07-28 | 2.1 | `LabelSpec.side` → circuitikz `l`/`l_` resolution is computed geometrically: circuitikz's default label side is 90° counterclockwise from the path's a→b direction vector; a requested side matching that compass direction uses `l=`, the opposite compass direction uses `l_=`, and a side on the wrong axis (e.g. "above" on a vertical path) falls back to `l=` since neither key can express it.
- 2026-07-28 | 2.1 | `kind` → circuitikz bipole name table (`BIPOLE_NAMES`) covers every path-eligible `Kind`; the controlled-source (`vcvs`/`vccs`/`ccvs`/`cccs`), `switch`, and `tline` mappings are best-effort guesses at real circuitikz macro names, unverified by a compiler — revisit when CI starts compiling goldens (roadmap 2.5). None of the roadmap 2.3 golden corpus circuits use these kinds.
- 2026-07-28 | 2.1 | The emitter renders `sheets[0]` only; multi-sheet composition (hierarchy) is out of scope until it is addressed elsewhere in the roadmap.
- 2026-07-28 | 2.2 | Node components with a resolved built-in circuitikz shape (`symbol.base` set, e.g. `nmos`/`npn`) emit `\node[base, xscale=-1 (if mirrored), rotate=R, label=...] at (...) {}`; TikZ composes per-node transform options left to right, so listing `xscale=-1` before `rotate` matches the IR's own "mirror before rotate" convention (`symbols.transform_offset`). Unverified against a compiler; a candidate for adjustment in the 2.5 compile-fix pass.
- 2026-07-28 | 2.2 | A node component's ref/value label uses circuitikz's `label=<pos>:{text}` node key (not the path component's `l=`/`l_=` fold, which has no node equivalent); side "auto"/unset defaults to `above`.
- 2026-07-28 | 2.2 | A node component whose symbol has no `base` (a generated subcircuit box, or any symbol circuitikz has no shape for) draws as a plain `\draw ... rectangle ...;` sized from `SymbolDef.size`/`rotated_size`, with a straight stub line from each pin to the nearest box edge (only drawn when the pin sits off the edge — SPEC_IR's "ports distributed left/right" convention means most generated pins sit exactly on the boundary already) and a centered ref-derived `\node`. An unresolvable symbol (not even in the file's own library) falls back to a 2×2 box rather than erroring, consistent with DESIGN §6 ("never emit silently-wrong output... draw a labelled placeholder box").
- 2026-07-28 | 2.2 | `--standalone` always loads `circuitikz` and `siunitx` regardless of `style.siunitx` (cheap and harmless unused), per the roadmap's literal "documentclass standalone, circuitikz, siunitx"; `style.extra_preamble` lines are inserted verbatim (D12) between the packages and `\begin{document}`.
- 2026-07-28 | 2.3 | **Corrects 2.1**: circuitikz's default resistor style is *American*, not European (manual: loading with no options implies `americanresistors`). The resistor variant is therefore emitted on every document (`\ctikzset{european resistors}` or `\ctikzset{american resistors}`) rather than only for the non-default case — otherwise SPEC_IR's European default (D11) silently rendered as an American zigzag. Declaring it outright also stops the rendering drifting with a circuitikz release.
- 2026-07-28 | 2.3 | **Corrects 2.1**: `BIPOLE_NAMES` guesses `vcontrolledsource`/`cccs` do not exist in circuitikz; the real names are `cvsource` (controlled voltage source) and `cisource` (controlled current source). Every name in the table is now checked to compile.
- 2026-07-28 | 2.3 | **Corrects 2.1**: a path component's label folds into the bipole slot (`to[R=$R_1$]`) only for *passive* kinds. The manual (§5.1.1) warns the shorthand sets the voltage/current property on sources, and rendering confirms `to[vsource=$V_1$]` draws an annotated voltage arrow rather than a name; `ACTIVE_KINDS` always get an explicit `l=`.
- 2026-07-28 | 2.3 | **Corrects 2.1**: circuitikz's `a` annotation already sits opposite the natural label side, so a flipped `l_` label collided with a plain `a` value. `a`/`a_` both stay opposite and only `a^` crosses over, so the emitter pairs `l`+`a` and `l_`+`a^` — the manual's own idiom. The value is placed on whichever side the ref label leaves free.
- 2026-07-28 | 2.3 | SPEC_IR's `capacitor_variant` is **deliberately not honoured**: circuitikz has no American/European capacitor style, and its only alternative plate shape (`cC`) is documented as the *polarized* capacitor, so mapping "american" onto it would change what the symbol means rather than how it looks. The emitter always emits `C`. Recorded rather than guessed, per the CircuiTikZ Reference Policy; SPEC_IR should either drop the field or define it against a specific circuitikz bipole.
- 2026-07-28 | 2.3 | **Corrects 1.3**: built-in transistor pin offsets now follow the *directions* of the real circuitikz anchors — control terminal due left at (-2, 0), the two channel terminals directly above and below the origin at (0, ±2), MOS bulk on the origin. The 1.3 geometry put the channel terminals at (±2, ±2), which matched no anchor and made the drawing visibly disconnected.
- 2026-07-28 | 2.3 | Node shapes are drawn at their own absolute size and are *not* scaled by the environment `scale=` that the grid pitch sets, so a rendered terminal can never coincide exactly with an integer grid point (nmos D sits 0.77 cm out = 1.54 units at the default pitch). The emitter therefore names each shape node and draws a short orthogonal lead from each documented anchor to the declared pin position. Leads follow rotation and mirroring for free, because TeX resolves anchors after the node's own transform.
- 2026-07-28 | 2.3 | TikZ node names are positional (`s2t<element index>`) rather than derived from the refdes — a refdes may contain characters TikZ rejects in a node name, and the index is unique per document and stable.
- 2026-07-28 | 2.3 | Pin-to-anchor names live in a tool-internal table (`symbols.BASE_PIN_ANCHORS`) keyed by `base` shape, not in the IR: they are knowledge about built-ins, which SPEC_IR already locates in `symbols.py`. A file-declared symbol whose `base` is not in the table gets no leads (its pins are still validated); revisit if that case ever arises.
- 2026-07-28 | 2.3 | A node component's ref label defaults to the side its pins leave clear (opposite the centre of mass of the pin directions) instead of always "above", which overlapped the symbol and its drain lead. The chosen side rotates with the component; an explicit `LabelSpec.side` still wins.
- 2026-07-28 | 2.3 | **Corrects 2.2**: `--standalone` uses `\documentclass[border=2pt]{standalone}`. Adding standalone's `tikz` class option defeats its cropping when circuitikz is loaded with `\usepackage`, producing a full letter page instead of a tight bounding box.
- 2026-07-28 | 2.3 | Golden regeneration is `pytest --update-golden` (a conftest option + `golden` fixture), per DESIGN §5's "single regeneration entry point". The roadmap's `spice2tikz --update-golden` is read as shorthand for that: the shipped CLI has no business knowing about `tests/`, and the CLI contract in CLAUDE.md does not list the flag.
- 2026-07-28 | 2.3 | Golden files are `<name>.tex` (snippet) and `<name>.standalone.tex`; the corpus is discovered by globbing `tests/corpus/*.schematic.json`, so a new corpus file is automatically covered by the golden, validation, determinism, and round-trip tests.
- 2026-07-28 | 2.3 | The §2.3 corpus is authored via a throwaway script that computes node pins with `resolve_pins` and writes canonical JSON; the committed artefacts are the JSON files. Hand-typing rotated pin coordinates is error-prone, and the canonical printer guarantees the byte-exactness `test_corpus_file_is_canonical_json` asserts.
- 2026-07-28 | 2.3 | Added a seventh corpus document, `mos_orientations`, which is a symbol-orientation reference sheet rather than a circuit: it is the only practical way to exercise all four rotations plus the mirror in one reviewable image, as the roadmap requires. `rlc_series` carries the American resistor variant so the D11 switch is covered by a golden too.
- 2026-07-28 | 2.3 | Corpus MOS components declare the bulk pin (invariant 8 requires every symbol pin) but leave it unwired, as a schematic with an implicit bulk-source tie does; circuitikz only draws a bulk terminal when passed the `bulk` key, so nothing dangles visually.
- 2026-07-28 | 2.3 | `emit.format_quantity` and `style.siunitx` are currently unreachable from the emission path: the Schematic IR carries no `Quantity` anywhere, so a value label can only be explicit text. They become live when the layout engine (§5) fills value labels from the Netlist IR, or if a future IR v1.1 adds an optional `value` to `PathComponent` (cf. roadmap 7.4).
- 2026-07-28 | 2.3 | `tests/golden/rc_lowpass.tex` cannot match SPEC_IR §5's "expected emission" listing exactly: that block shows `a=\SI{10}{\kilo\ohm}` annotations, but the §5 *Schematic IR* listing it is paired with carries no `value_label` (and the IR has no value field to derive one from), so the two normative blocks are mutually inconsistent. The corpus file stays byte-identical to the §5 IR listing (locked by 1.2) and the golden shows what the emitter actually produces; other corpus circuits carry explicit `value_label` text so the feature is still covered.
- 2026-07-28 | 2.3 | Sources are emitted as the **American** shapes (`american voltage source`, `american current source`, and the controlled equivalents) rather than the `vsource`/`isource` shorthands — user decision after reviewing the rendered variants. The shorthands follow circuitikz's `europeanvoltages` flag, whose default is a bar with no polarity marks, and a schematic should show which terminal is positive. The long spelling is also the portable one (`vsourceAM` only exists from circuitikz 1.8; TeX Live ships 1.4.6) and avoids `\ctikzset{american voltages}`, which would additionally switch voltage *annotation* arrows to +/- signs. No `source_variant` style field was added: one convention is hardcoded for now (decided against extending SPEC_IR).
- 2026-07-28 | 2.3 | **SPEC_IR §2 amended** (user decision): `capacitor_variant` is *removed* from `StyleDefaults`. It had no referent anywhere — circuitikz has no american/european capacitor key, and neither standard distinguishes them (ANSI and IEC both draw a non-polarized capacitor as two parallel plates). The only capacitor symbol variation that means anything is *polarization*, which is a property of the device, not a drawing style, so it belongs in the kind taxonomy if it is ever wanted. Files still carrying the field load with the usual unknown-field warning, so no major version bump: the IR stays `1.0` while the tool is pre-alpha, as CHANGELOG already states for the `0.x` series.
- 2026-07-28 | 2.3 | **SPEC_IR §2 amended** (user decision): added `inductor_variant: "american"|"european"|"cute"`, default `cute`. Inductors genuinely have three circuitikz styles, the spec had no field for them, and the emitter was inheriting circuitikz's `cuteinductors` default by accident — the same latent bug as the resistor default. The chosen variant is now always declared alongside the resistor one, so no symbol depends on a package default. `cute` is the default because it is circuitikz's own, so existing renders are unchanged; the field exists to override it.
- 2026-08-29 | 2.4 | `netlist_ir.dump`/`schematic_ir.dump` pass `newline="\n"` to `write_text` — without it Python translates `\n` to the platform line ending, so the byte-identical-output promise (CLAUDE.md rule 4) held only on POSIX and the canonical-dump tests failed on Windows.
- 2026-08-29 | 2.4 | The CLI writes emitted LaTeX through `sys.stdout.buffer` rather than `print`/`sys.stdout.write` — Windows text-mode stdout translates `\n` to `\r\n`, so `spice2tikz x.json > x.tex` would otherwise produce different bytes per platform.
- 2026-08-29 | 2.4 | A Netlist IR input (`.netlist.json`, and later `.sp`) with no `--dump-netlist` exits 1 with "layout not yet implemented (roadmap section 5); use --dump-netlist"; with a dump requested it exits 0. Roadmap 4.4 specifies this for `.sp`; applying it to the netlist-IR path too keeps one rule for "this input has no route to LaTeX yet". It changes 1.5's behaviour, where any loadable IR file exited 0.
- 2026-08-29 | 2.4 | `--dump-netlist` / `--dump-layout` write their file *before* validation runs, so a document that fails validation can still be dumped and inspected; they are additional outputs, not replacements, so stdout still receives the LaTeX.
- 2026-08-29 | 2.4 | `--config` reads TOML through `src/spice2tikz/_toml.py`, which delegates to `tomllib` on Python 3.11+ and falls back to a small in-tree subset parser on 3.10 — `tomllib` is 3.11+ and D1 forbids a runtime dependency on a back-port. The subset covers tables, strings, booleans, numbers and arrays; both paths are tested against the same acceptance suite.
- 2026-08-29 | 2.4 | `_toml` imports `tomllib` via `importlib.import_module` rather than `try: import tomllib` — mypy is pinned to `python_version = "3.10"`, where a static import needs an ignore comment that would be wrong for every interpreter that actually runs it.
- 2026-08-29 | 2.4 | Style precedence is built-in defaults < the document's `style` block < `--config` < `--style`; `--style extra_preamble=...` appends one line per occurrence rather than replacing the list, since preamble lines accumulate.
- 2026-08-29 | 2.5 | `tests/test_compile.py` compiles every `tests/golden/**/*.standalone.tex` with `latexmk -pdf` and skips the whole module when `latexmk` is absent, per the roadmap's "local auto-skip". It sets `TEXMFVAR` into the pytest tmp dir so a run never writes to the user's home, and includes a deliberately-broken document that must fail — a compile check that passes everything is worse than none.
- 2026-08-29 | 2.5 | The CI compile job runs in the `texlive/texlive:latest` container and invokes `pytest tests/test_compile.py`, rather than a shell loop over `latexmk` — the skip/collection logic then lives in one place and CI exercises the same code contributors run.
- 2026-08-29 | 2.5 | `tools/render_goldens.py` also accepts Ghostscript (`gs`/`gswin64c`) as a PDF→PNG converter and globs goldens recursively, so goldens grouped in subdirectories (`asc/`, `layout/`) render too and the name shown keeps its subdirectory.
- 2026-08-29 | 2.5 | Verified against TeX Live 2026 / circuitikz 1.8.x: all seven §2.3 standalone goldens compile clean, and the rendered images were reviewed (components present, all four rotations plus the mirror correct, labels readable, wires meeting the intended pins, junction dots where expected, no overlaps). No golden needed a fix.
- 2026-08-29 | 4.1 | Stage 1 returns the deck title as the first `SpiceLine` with `is_title=True` rather than as a separate return value — the roadmap fixes `assemble_lines(text, warnings) -> list[SpiceLine]`, and the title has to stay observable from stage 1 for its own unit tests.
- 2026-08-29 | 4.1 | The first physical line of a deck is always the title, even when it parses as a card, unless the deck opens with `.title`; a leading `*` and surrounding whitespace are stripped from it (SPEC_IR §5 turns `* RC low-pass` into the title `RC low-pass`).
- 2026-08-29 | 4.1 | Nothing else is stripped from the title line — no inline-comment handling — because a title is free text and a `;` in it is part of the title.
- 2026-08-29 | 4.1 | A `.title` card anywhere in the deck overrides the first-line title, and the last one wins; ngspice treats the card as a title replacement rather than an addition.
- 2026-08-29 | 4.1 | Inline comments start at `;` anywhere, or at `$` only at the start of a card or after whitespace — ngspice's own restriction, and it keeps `$`-prefixed parameter references inside a token intact (`10k$suffix` is one token, `10k $ note` is a comment).
- 2026-08-29 | 4.1 | `*` full-line comments are recognised after leading whitespace, not only in column 1 — real decks indent them, and no other card can begin with `*`.
- 2026-08-29 | 4.1 | Continuations join with exactly one space and the logical card keeps the line/column of its *first* physical line; comment and blank lines between a card and its `+` continuation are transparent.
- 2026-08-29 | 4.1 | A `+` continuation with no card above it is the one unrecoverable parse error (`IRError`, CLI exit 1) — it changes what the circuit *is*, unlike everything else, which degrades with a warning per DESIGN §6.
- 2026-08-29 | 4.1 | `.end` is consumed by stage 1, and remaining non-blank lines produce one warning naming the `.end` line and the count; a `.end` card may carry trailing text (`.end of deck`).
- 2026-08-29 | 4.1 | Diagnostics are `file:line:column: message`, with `<input>` standing in for the file name when the caller named no source (`parse_spice` without `source=`).
- 2026-08-29 | 4.1 | A UTF-8 BOM is stripped as bytes in `load_spice` *and* as U+FEFF in `assemble_lines`, since text may reach stage 1 already decoded; CRLF and lone CR both normalise to LF so line numbers match what an editor shows.
- 2026-08-29 | 4.2 | Node names, `.model` names and `.subckt` names are lowercased (ngspice matches them case-insensitively and one spelling must win); a refdes keeps its original spelling (D9), and a `H`/`F` card's controlling-source reference is resolved case-insensitively back to the defining component's spelling so SPEC_IR §4 invariant 3 compares equal.
- 2026-08-29 | 4.2 | `models` dictionary keys are lowercase like `subcircuits` keys, which SPEC_IR §1 mandates only for the latter — `Component.model` is documented as "key into models", so the two must agree, and case-insensitive matching forces one canonical spelling.
- 2026-08-29 | 4.2 | `.model` *type* names are lowercased before polarity lookup (`NPN` → `npn`); the stored `ModelDef.type` is that lowercased form, while `ModelDef.raw` keeps the card verbatim.
- 2026-08-29 | 4.2 | The card tokenizer makes `( ) , =` separate tokens and keeps `{...}`/quoted strings whole, so `k=v`, `k =v`, `k= v` and `k = v` all parse identically and `SIN(0 1 1k)` needs no special lexing.
- 2026-08-29 | 4.2 | A `V`/`I` card's `value.raw` is the verbatim text after the two nodes, parsed through `parse_quantity` so a bare number (`V1 in 0 5`) still yields `value`/`unit` while a multi-token spec (`AC 1`) degrades to raw only — exactly the SPEC_IR §5 normative shape.
- 2026-08-29 | 4.2 | Source-specification parameter names are fixed and prefixed by form: `dc`, `ac`, `ac_phase`, `sin_*`, `pulse_*`, `exp_*`, and open-ended `pwl_t<n>`/`pwl_v<n>`.
